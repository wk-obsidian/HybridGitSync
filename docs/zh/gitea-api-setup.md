# Gitea API 模式配置

本指南介绍如何配置 Hybrid Git Sync 使用 Gitea REST API 同步 Obsidian vault。

## 前置条件

- Gitea 账户（自托管或 [gitea.com](https://gitea.com)）
- Gitea 上已创建用于 vault 的 Git 仓库
- 具有 `repo` 权限的个人访问令牌

## 步骤 1：创建个人访问令牌

1. 登录你的 Gitea 实例
2. 进入 **设置** → **应用** → **个人访问令牌**
3. 点击 **生成新令牌**
4. 输入描述性名称（如 "Obsidian Sync"）
5. 选择 **repo** 范围（完全控制仓库）
6. 点击 **生成令牌**
7. **立即复制令牌** — 之后无法再查看

## 步骤 2：配置插件

打开 Obsidian → 设置 → Hybrid Git Sync，配置以下参数：

| 设置项 | 值 | 示例 |
|---|---|---|
| 后端模式 | API | — |
| API 提供商 | Gitea | — |
| 自定义 API URL | 你的 Gitea API 地址 | `https://gitea.com/api/v1` |
| API Token | 你的个人访问令牌 | `abc123...` |
| 远程仓库 | `用户名/仓库名` | `walkskyer/my-vault` |
| 分支 | 同步分支 | `main` |

### API URL 格式

API URL 必须以 `/api/v1` 结尾：

| Gitea 实例 | API URL |
|---|---|
| gitea.com | `https://gitea.com/api/v1` |
| 自托管 | `https://你的域名/api/v1` |

**注意：** 不要添加尾部斜杠。

## 步骤 3：测试连接

1. 配置完成后，插件会自动检查仓库是否可访问
2. 如果成功，状态栏会显示同步状态
3. 点击 **立即同步** 执行首次同步

## 故障排除

### "API 后端不可用"

- 验证 API URL 是否正确（必须以 `/api/v1` 结尾）
- 检查令牌是否有效且未过期
- 确保仓库存在且令牌有访问权限
- 在高级设置中开启 **调试模式** 查看详细日志

### "无法连接远程"

- 检查网络连接
- 验证 Gitea 实例是否可访问
- 自托管实例请确认服务器正在运行

### 同步静默失败

- 在高级设置中开启 **调试模式**
- 查看控制台日志中的错误信息
- 确认仓库格式为 `用户名/仓库名`（不要有前导斜杠）

## 注意事项

- **不支持 OAuth**：Gitea OAuth 需要每个实例单独配置，因此仅支持个人访问令牌认证
- **自托管实例**：自托管 Gitea 必须填写自定义 API URL
- **文件大小限制**：取决于你的 Gitea 实例配置（默认值可能不同）
